# Fact-Check-X v1.1.15 acceptance record

Fact-Check-X v1.1.15 fixes Windows stage-artifact links, DKnow knowledge-library source capture and recommendation semantics. It does not add a platform, external model API or workflow stage.

## Accepted behavior

1. Every generated stage artifact is returned only after the file exists, with its native absolute path, a standards-compliant `file://` URI and a ready-to-use Markdown link.
2. Windows drive-letter paths are encoded as valid file URIs. Portable report packages replace host-specific links with relative package links and expose no host path.
3. DKnow inline citations and knowledge-library sources are both captured. The same normalized URL is stored once with `citationScope=inline_and_global`; knowledge-library-only sources use `citationScope=global`.
4. A knowledge-library source supports a factual claim only when its captured text semantically supports that atomic claim. The entire source pool is never inherited automatically.
5. Pure operational recommendations use `claimType=recommendation` and `faithfulness=not_applicable`. They skip Trusted Search, appear as recommendations and are excluded from factual accuracy, coverage and hallucination metrics.
6. A recommendation containing a policy rule, condition, number or effective date must split that factual premise into a separate `fact` knowledge point and verify it normally.
7. Existing four-stage workflow, dynamic `N>=1` platform selection, factual evidence gates and Computer Use recovery remain unchanged.
