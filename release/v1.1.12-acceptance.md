# Fact-Check-X v1.1.12 acceptance record

Fact-Check-X v1.1.12 repairs DKnow citation capture on the current product interface. It adds no platform, scoring metric, report redesign or external model dependency, and the four-stage contract is unchanged.

## Accepted behavior

1. Every footnote marker cited in a DKnow answer produces exactly one reference. A citation card is never discarded because its link is missing from the page; such a card is kept as an explicit link-missing reference.
2. A marker and its source URL always come from the same citation card. The current interface's `data-url2` link is preferred over the legacy `data-url`, and an image or other asset URL is never accepted as a reference source.
3. Each reference retains the card's traceability text and clause path, so a captured DKnow reference always carries readable evidence.
4. DKnow source URLs keep their hash route during normalization, because the route identifies the policy document.
5. Legacy DKnow citation cards continue to be captured, and numeric footnote markers are preferred over internal identifiers.

## Verification evidence

- Replayed against the real captured DOM of a live run on the current interface: `dknowc-chat` marker coverage rose from 4 of 7 to 7 of 7, the two references that had resolved to an image URL are gone, and all 7 references now carry evidence text where previously none did.
- `dknowc-deep-research` covers markers 1 through 24 on the same page. The previous 29 references contained two duplicate markers and four entries with no marker, and were missing marker 17 entirely.
- A new regression drives a real browser DOM containing the image-link trap and a legacy citation card. It fails on the previous code with the reported symptom and passes on this version.
- 11 JavaScript collector checks and 18 Python package/module checks pass.
