# Fact-Check-X v1.1.11 acceptance record

Fact-Check-X v1.1.11 adapts the two DKnow collectors to the current product interface while preserving the existing four-stage fact-checking contract. It adds no platform, scoring metric, report redesign or external model dependency.

## Accepted behavior

1. `dknowc-chat` and `dknowc-deep-research` both enter through `https://yun.dknowc.cn/wlcb/szx/#/` and use the current product controls.
2. When both DKnow platform IDs are selected, the original question is submitted once. The completed standard answer is saved before Deep Trace is started in the same conversation.
3. Standard and Deep Trace answers, references, screenshots and HTML evidence are stored as separate platform results and cannot overwrite each other.
4. Deep Trace may complete inline or on a same-product result page. An unrelated popup is rejected; a missing, incomplete or failed result remains a capture failure and enters the existing retry and Computer Use recovery gate.
5. Homepage welcome and recommendation content cannot satisfy answer extraction. The existing stage checkpoints, authority semantics and Stage-3-to-Stage-4 data ownership remain unchanged.

## Verification evidence

- A real browser run on the current DKnow interface submitted one policy question once, captured a 2,666-character standard answer with 12 references, then captured a separate 6,269-character Deep Trace answer with 34 references.
- The two platform results produced different screenshot and HTML evidence hashes, proving that the ordinary result was not overwritten by Deep Trace.
- Collector regressions cover shared-session planning, inline and same-product result handling, missing-result failure, login recovery, reference extraction and homepage recommendation filtering.
- Public package, module, interaction, authority configuration, governance and deterministic-release checks must pass on the frozen v1.1.11 source before publication.
