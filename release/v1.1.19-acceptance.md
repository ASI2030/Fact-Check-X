# Fact-Check-X v1.1.19 acceptance record

Fact-Check-X v1.1.19 hardens browser capture recovery and authority-stage correction without replacing the Playwright driver, adding a platform, changing scoring, or introducing an external model dependency.

## Accepted behavior

1. Doubao progress text such as `正在查证` is never accepted as a completed answer; placeholders and near-empty answers fail the capture gate.
2. Selector drift is handled by a recovery layer that discovers candidates, produces selector proposals and requires deterministic program validation before execution. The host browser or Computer Use remains the primary recovery path; agent-browser is optional diagnostic input and is not a runtime dependency.
3. A platform question is submitted at most once per capture lifecycle. After any send attempt, confirmed submission or observed answer, recovery may continue extraction on the same page but may not re-submit the question. Only a page closure before submission permits a fresh attempt.
4. `authoritativeFinding` is preserved verbatim even when it begins with the knowledge-point description.
5. A finalized authority stage can be reopened only through `reopen-authority`. The command verifies the locked manifests and hashes, archives the prior revision, removes active derived results, and returns the gate to `searched` for a controlled re-finalization.

## Verification evidence

- Both collector mirrors pass the selector-drift, intermediate-state, login-recovery and single-submission regressions.
- A real-browser DOM replay proves stale input and answer selectors recover while the submission count remains one.
- The authority pipeline completes `finalize -> archive/reopen -> assessment correction -> finalize` and preserves the full finding in both finalizations.
- The complete package prepares its runtime and passes Python, JavaScript and browser-DOM checks after a clean unpack.
- Two independent clean public builds are byte-identical. The frozen formal-package candidate SHA-256 is `2dc3b03f3920cf0b6fd47ec98c7c8cb8a495e46502a626989f6b0c84f600848f`.

## Release boundary

- Authorized channels: GitHub, SkillHub and the local WorkBuddy installation.
- GitHub publication must bind a clean source commit and immutable release assets.
- SkillHub submission is recorded as pending until the platform returns completed review and signature state.
- WorkBuddy is recorded as updated only after the installed tree and running package version are read back.
- Public receipts and final artifact hashes are appended only after each channel has been independently verified.
